# 任务二个人心得：API + HTTP 方案

第二种方法的主要启发来自课上老师讲的内容，即通过网络分析提取需要的字段。在实际操作中，我按照老师讲解的方法分析网站的网络请求，并尝试直接从接口返回的数据中提取任务所需的信息。

但我在运行过程中发现，网络分析并不能提取到所有需要的字段。部分字段可以直接通过 API 返回，例如成交时间、竞得人、成交价格、地块位置和详情页 URL 等；但还有一些字段只出现在详情页中，无法仅通过列表接口直接获取。因此，我最终采用了 API + HTTP 的方法：先通过 API 获取列表数据和详情页 URL，再使用 HTTP 请求访问详情页，解析其中的两层 iframe，并补充交易土地面积等字段。

在运行过程中，我也明显感觉到第二种方法比第一个 Playwright 方法更加方便、迅速。第一个方法需要启动浏览器、等待页面加载，并逐页进入详情页面；第二种方法不需要启动浏览器，可以直接请求接口和详情页，因此减少了浏览器加载和页面切换所需要的时间，运行过程也更加简洁。

通过第二种方法，我进一步理解了网络分析并不一定能够一次获得任务要求的全部数据。在实际开发中，需要先分析接口能够提供哪些字段，再判断缺少的字段应当从哪里补充。将 API 获取列表数据和 HTTP 解析详情页结合起来，既保留了网络分析方法速度较快的优点，也能够获取任务要求的完整字段。
